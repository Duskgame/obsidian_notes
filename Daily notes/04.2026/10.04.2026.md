## Progress:

Kwizz EditQuizScreen UI — question list with view/edit modes:
- Redesigned question list UX: questions display-only by default, each row has Edit and Delete icon buttons
- Clicking Edit switches that question to inline edit mode (OutlinedTextFields + Save/Delete icons); Edit button becomes Save (check icon)
- Save button only visible when both question and answer fields are non-blank — if empty, only Delete is shown (forces discard of empty questions)
- `editingQuestionId: String?` tracked as local `remember` state in the composable (not ViewModel) — pure UI concern, one question editable at a time
- `remember(question.questionId)` key used in `QuestionEditItem` so local text state resets when the item's question data changes after saving
- "Add question" is a `TextButton` at the bottom of the `LazyColumn` as the last `item {}` block — scrolls with the list
- Replaced `addQuestion(text, answer)` in `EditQuizViewModel` with `addEmptyQuestion(): String` — adds a blank question and returns its ID so the screen can immediately put it into edit mode
- `Scaffold` used in `EditQuizScreen` to handle `innerPadding` from the system

Kwizz — dropped separate `AddQuestionScreen` route in favor of inline add in `EditQuizScreen`

Concept: Shared ViewModel across nav destinations — scope a ViewModel to a parent `NavBackStackEntry` via `navController.getBackStackEntry(route)` so two composable destinations share the same instance

Kwizz EditQuizScreen — full rework with action pattern and screen split:
- Added `EditQuizAction` sealed interface with actions: `QuizNameChanged`, `AddQuestion`, `ConsumeNewQuestion`, `UpdateQuestion`, `DeleteQuestion`, `Save`, `Upload`
- Replaced all individual public ViewModel functions with a single `onAction(EditQuizAction)` — all internal functions made `private`
- Added `hasUnsavedChanges: Boolean` to `EditQuizUiState` — set `true` on any modifying action, `false` on save; drives Save button `enabled` state
- Moved `isNewQuiz` out of `EditQuizUiState` into a plain `val` on the ViewModel — it's set once and never changes, so it's not state
- `addEmptyQuestion()` now communicates the new question's ID via `newAddedQuestionId: String?` in UiState instead of returning it — consumed in the composable via `LaunchedEffect` + `ConsumeNewQuestion` action to reset it to null
- Split `EditQuizScreen` into `EditQuizScreen` (ViewModel setup) + `EditQuizContent` (pure UI, previewable)
- Split `QuestionEditItem` into three composables: `QuestionItem` (switches modes), `QuestionViewItem` (display), `QuestionEditItem` (edit fields)
- Added `QuizName` composable with same view/edit toggle pattern — `remember(name)` key ensures text resets when ViewModel loads existing quiz name asynchronously
- `upload()` now resets `uploadSuccess = false` on each new upload attempt

Fixed: Ktor 3.4.2 incompatible with Kotlin 2.1.0 (metadata version mismatch) — downgraded to Ktor 3.0.3
