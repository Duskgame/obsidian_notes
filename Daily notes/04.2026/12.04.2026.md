## Progress:

### Kwizz — UI cleanup & architecture session
- Fixed `BrowseViewModel` loading bug (`isLoading` was set to `false` instead of `true` before the API call)
- Fixed `QuizUiState.userGuess` mutability (`var` → `val` to restore data class immutability)
- Fixed `EditQuizViewModel.deleteQuestion` bug — was appending all current questions to `deletedQuestion` instead of just the removed one
- Added action pattern to Browse: created `BrowseAction` sealed interface, split `BrowseScreen` into container + content composable
- Fixed top app bar overlapping screens — `modifier` with `innerPadding` was only forwarded to `StartScreen`, not the other three
- Connected frontend to backend: identified `android:usesCleartextTraffic` as the blocker, added `PUT /quizzes/sync` upsert endpoint to backend to handle both create and update in one call
- Implemented modern type-safe navigation using `@Serializable` route objects, `composable<T>`, and `toRoute<T>()` — replaced old string-based routing entirely
- Embedded `quizName` in navigation routes to drive the app bar title directly from the back stack, without callbacks or shared ViewModels
- Fixed `QuizName` composable always being in editing mode — moved `isNewQuiz` into `EditQuizUiState` so the initial state is known before the async quiz load completes
- Consolidated four separate `ViewModelFactory` classes into a single `AppViewModelProvider` using `viewModelFactory { initializer {} }` and `CreationExtras`
- Removed `quizId` from `QuizScreen` and `EditQuizScreen` composable parameters — ViewModels now read it directly from `SavedStateHandle` via `savedStateHandle.toRoute<T>()`
