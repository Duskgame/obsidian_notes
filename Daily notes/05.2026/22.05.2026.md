## New Notes:

- [[CAP Theorem]] — the CP vs AP trade-off every distributed system must make
- [[Eventual Consistency]] — AP systems allow divergence, nodes converge after partition heals
- [[Vector Clocks]] — per-node counters that detect concurrent conflicting writes
- [[Lamport Timestamps]] — logical counters for causal ordering across distributed nodes
- [[Monotonic Clocks]] — clocks that never go backwards; reliable for durations, not cross-node ordering
- [[Total and Partial Order]] — total order is one definitive sequence; partial order allows concurrency
- [[Message Group Pattern]] — order per group key, parallel across groups; middle ground between FIFO and unordered
- [[Delivery Semantics]] — at-most-once, at-least-once, exactly-once and when to use each
- [[Deduplication ID]] — unique message IDs that make at-least-once consumers effectively-once
- [[Throughput and Latency]] — the two performance dimensions and how they trade off
- [[Load Shedding]] — deliberately dropping excess work to protect system stability
- [[Backpressure]] — consumer signals producer to slow down; no data loss unlike load shedding
- [[RPC]] — calling remote functions as if they were local; gRPC, tRPC, JSON-RPC
